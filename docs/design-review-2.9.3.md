# Design review — IlTa 2.9.3 UI (home · section · rule)

Version reviewed: **IlTa 2.9.3** (working tree: `versionName = "2.9.3"`, `app/build.gradle.kts`).
Artifacts: `art/screenshots/132_home_final.png`, `art/screenshots/133_section_clean.png`, `art/screenshots/131_rule_polished.png` (light theme, RU). Code read for this review (no edits, no gradle): `ui/theme/Theme.kt`, `ui/components/Common.kt`, `ui/App.kt`, `ui/screens/TopicsScreen.kt`, `ui/screens/SectionScreen.kt`, `ui/screens/RuleDetailScreen.kt`, `data/ProgressStore.kt`, plus the current bundled content (verified counts match the screenshots: 630 + 310 + 1080 = **2020**, 90 per tense theme).

**Verdict: borderline (leaning good) — 7/10.** The visual language is coherent and much cleaner than the pre-2.9 builds: one 20 dp content margin everywhere, a consistent 12–14 dp vertical rhythm, a restrained outlined-card system (20 dp radius), a clear type scale, a genuinely good formula block (monospace + tinted container + aligned heading), tidy example rows, and no leftover filler phrases (the 2.9.3 cleanup removed the footer/description/“чем больше отвечаете…” lines — confirmed in screenshots and in the code diff). What keeps it from “good” is a set of visible polish defects: an empty band above the back app bar on both inner screens, a coloured dot at the end of every progress bar even at 0 %, mid-word title truncation and misaligned chip/chevron in section cards, duplicated titles/counts, and low-contrast level-coloured micro-labels.

| # | Severity | Issue | Exact suggested change |
|---|---|---|---|
| 1 | **high** | **Empty band above the app bar on inner screens.** On Section and Rule screens the back-arrow row starts ~55–60 dp lower than the home header (screenshot: status bar ends at y≈80 px, the back row begins at y≈320 px; on Home the title starts at y≈183 px). Cause: the root `Scaffold` already applies the status-bar inset via `innerPadding`, and `BackTopBar`'s `CenterAlignedTopAppBar` applies status-bar window insets again — double inset. | Consume the inset once. Either (a) give `BackTopBar` `windowInsets = WindowInsets(0, 0, 0, 0)` (import `androidx.compose.foundation.layout.WindowInsets`) because the parent already padded by `innerPadding`, or (b) move the app bar into the `Scaffold` `topBar` slot and stop applying the top `innerPadding` to these two screens. Target: the back arrow/title sit exactly where the Home title sits (one status-bar inset below the system bar). |
| 2 | **medium** | **Progress bars end with a coloured dot that reads as “100 %” at 0 %.** Every `AccuracyBar`/`ThinProgressBar` shows a small dot at the right end of the track (Material 3 1.3 “stop indicator”), tinted with the accent colour (primary / A1 green / B1 amber). Next to “0 %” it looks like a completed marker, not an empty bar. | Pass an empty stop-indicator draw to `LinearProgressIndicator` (Material 3 1.3: `drawStopIndicator = {}` — or the equivalent `stopIndicator` lambda); or, if the dot is kept as a decorative track cap, colour it `MaterialTheme.colorScheme.outlineVariant` and use it only when `progress > 0`, never at 0 %. |
| 3 | **medium** | **Section theme cards: truncated titles + misaligned right column.** “Present Perfect Continuous (настоящее совершённое длительн…” breaks mid-word with an ellipsis; the level chip floats at the end of the title block while the chevron “›” sits lower, at the progress row — two right-aligned elements at different heights. | In `RuleRowCard` (SectionScreen.kt): move `LevelChip` and `›` into one `Row(verticalAlignment = Alignment.Top)` in the card's top-right corner; render the title as the English name on up to 2 lines with the Russian name as a `labelSmall` second line (or allow 3 lines / reduce to `titleMedium` 18 sp). Target: no “…” inside a word, chip and chevron top-aligned, progress row full width underneath. |
| 4 | **medium** | **Duplicated headings and inconsistent CTA subtitles.** The app-bar title repeats the header-card title (“Времена” twice; “Present Simple: форма и значение” twice). The Section CTA subtitle repeats the hero count (“1080 вопросов”) and means the whole pool, while the Home CTA says “10 вопросов” (session size) and the Rule CTA says “30 вопросов” (session size) — three different meanings for the same slot. | Keep one H1 per screen: either drop the title from `SectionSummaryCard`/`RuleSummaryCard` (keep icon + counts + chip) or show the app-bar title only when the header scrolls away. Make every primary-CTA subtitle describe the **session** (“10 вопросов за тренировку”), not the pool; remove the duplicated “1080 вопросов” under “Тренировать раздел”. |
| 5 | **medium** | **Colour accessibility / theme system.** Level-coloured percentages in section cards are 12 sp bold in `levelColor` values on a near-white background: A1 #059669 ≈ 3.6:1, A2 #0D9488 ≈ 3.2:1, B1 #D97706 ≈ 3.0:1 — below WCAG AA 4.5:1 for normal text. The level palette is hard-coded (`Common.kt: levelColor`) and does not adapt to dark theme or to dynamic colour, which is **on by default** (`ProgressStore.kt`: `dynamicColor = true`) — that is why the screenshots show a wallpaper palette (lavender background #FAF8FF, navy primary #2A4174, slate secondary #6E7488) instead of the designed palette (teal #0F766E / amber #B45309 / warm #FBFAF6 from `Theme.kt`). | Use text-tone variants for small coloured labels (A1 #047857, A2 #0F766E, B1 #B45309, B2 #B91C1C on light; lighter tones on dark), or render the percentage in `onSurfaceVariant` and keep the level colour only for the bar and the chip. Decide the dynamic-colour policy explicitly: default `dynamicColor = false` to preserve the brand palette, or map `levelColor` to dynamic tonal roles; add dark-theme screenshots to the review set (the code has a complete `DarkColors` scheme and correct status/nav-bar icon handling, but no dark capture was provided). |
| 6 | **low–medium** | **Formula block vs example list blur together, and example rows have a false affordance.** The formula container uses `surfaceVariant` at 45 % (#EEEEF6) and example rows use it at 28 % (#F3F2FA) — the two block types are nearly the same tone, so the “formula / examples” hierarchy is weak. Every example is prefixed with “›”, the same glyph used for navigation chevrons, but the rows are not tappable. Also, long formula lines (e.g. tenses_08 §1 “had been + V-ing — утверждение”, tenses_12 “(−) S + will not have been + V-ing”) exceed ~30 monospace characters and will wrap on 360–393 dp screens. | Increase formula contrast: `Surface(color = MaterialTheme.colorScheme.surfaceVariant)` (no alpha) or a 60 % `primaryContainer` tint, and make example rows transparent/18 % with a hairline divider — or keep both but give the formula block a small “FORMULA”/icon label. Replace the leading “›” in example rows with a neutral “•” (matching the bullets) or a short accent dash, and only show a chevron if tapping opens a translation. Split formula and comment into separate lines in the content (or set 15 sp / `softWrap` handling) so formulas never break mid-formula. |
| 7 | **low** | **Micro-copy and small consistency polish.** “10 вопросов · выбрать темы” (infinitive after a middot) reads unfinished; the rule progress row wraps to two lines because of “30 вопросов в тренировке · 90 вопросов в теме” + “Ошибки снижают прогресс”, and that right caption is a service phrase; CTA verbs are inconsistent (Home “Тренировка” noun vs “Тренировать раздел/тему”); button heights differ (Home 58 dp vs inner 64 dp) and subtitle alpha differs (Home 0.8 vs inner 1.0); numbers ≥ 1000 lack the Russian thousands separator; the zero state “Вы изучили 0% грамматики” is a dead end. | “10 вопросов · выбор тем”; move “Ошибки снижают прогресс” out of the row (small hint under the bar) and shorten the row to “30 в тренировке · 90 в теме” so it stays single-line; unify CTA pattern (all verbs: “Тренировать”), height 64 dp and subtitle alpha 0.8 everywhere; format “2 020”, “1 080”; for the 0 % state show “Пока 0 % — начните с первой тренировки” (one line) instead of the learned-0 % sentence. |

## Strengths (what is already good)

- **Hierarchy:** brand → learning-progress card → primary CTA → mistake review → section list on Home; summary → CTA → theme list on Section; header → progress → rule sections → CTA on Rule. The eye path is predictable in all three screens.
- **Spacing & alignment:** one 20 dp content margin across the three screens, 16 dp card padding, 12–14 dp inter-card gaps, right edges aligned; nothing collides or hugs edges.
- **Typography:** clear 28/23/20/16/16/14/12 scale via `AppTypography`; sentences use `LineBreak.Heading` + 26 sp line height (no orphan words); formula lines are the only monospace text — a good, meaningful exception.
- **Formula block:** tinted rounded container inside the section card, monospace semibold, evenly spaced lines, aligned with the accent-bar heading — the best-looking part of the rule screen.
- **Examples:** grouped inside the section card as compact rounded rows, consistent with the bullet list's text column — easy to scan.
- **Cards:** a single restrained card style (20 dp radius, 1 dp outline, surface) reused everywhere; level chips are small and quiet.
- **Cleanliness:** no placeholder/filler copy on the three screens; the 2.9.3 cleanup (footer “Всё работает офлайн…”, “Чем больше отвечаете…”, section descriptions) is visible in the code diff and the screenshots are clean. Rule summaries are deliberately hidden for the tense themes to avoid duplicating the formula block — good call.
- **Consistency RU/EN:** all strings go through `tr()`, sentence case is consistent, level labels A1–B2 are language-neutral.
- **Theme plumbing:** Material3 edge-to-edge, `ThemeMode` (system/light/dark), status/nav-bar icon appearance handled in `Theme.kt` — the foundation for a correct dark theme is there.

## Verified / non-blocking notes

- Displayed content counts are consistent with the bundled data: 2020 total = articles 630 + prepositions 310 + tenses 1080; 90 questions per tense theme; section meta “12 тем · 1080 вопросов” and CTA numbers are not mismatched — good.
- Bottom navigation: selected pill uses `secondaryContainer` (slate in the dynamic palette) while the CTA uses `primary` (navy); it is acceptable but the pill is visually closer to the streak badge than to the primary action — a subtle hierarchy point, not a defect.
- Repeated “90 вопросов” on every section-screen card carries little information (all cards in a section show the same number); consider showing only “12 тем” there and leaving question counts to the rule screen.
- The Home CTA's “Работа над ошибками” disabled card is handled correctly (55 % alpha over the whole card, no chevron) — the greyed state is readable.
- Dark theme could not be visually assessed (no dark screenshots); the code-level risks are the hard-coded level colours and the dynamic-colour default described in #5. Please add a dark-theme screenshot set for the next review.

## Summary — priorities for the next build

1. Fix the double top inset on Section/Rule screens (#1) — the most visible defect.
2. Hide or neutralise the progress-bar stop dot at 0 % (#2).
3. Rework the section theme card internals: no mid-word truncation, chip+chevron top-aligned (#3).
4. Remove duplicate H1s / duplicated counts and unify CTA subtitles to the session size (#4).
5. Make small coloured labels meet 4.5:1 and decide the dynamic-colour / dark-theme policy (#5).
6. Separate formula block from example rows visually and drop the misleading “›” affordance (#6).
7. Copy polish bundle (#7).

All items are UI-only and do not require content changes; the screenshots already show a solid, consistent base.
