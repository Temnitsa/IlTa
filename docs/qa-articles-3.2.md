# QA review — IlTa 3.2 articles (themes 1–9)

**Verdict: fail** — the 3.2 article restructure is mostly in good shape (question pools untouched, English examples and translations clean, no exam framing in the JSON content), but the acceptance criteria are not met: one match question is unsolvable as stored, one match right is invalid English for the rule it illustrates, several match cues are inaccurate, large parts of some rule bodies have no matching examples, and the project documentation still frames theme 9 as an IELTS/academic-writing topic.

Reviewed read-only: all nine `articles_01…09` files — 9 rules / **43 sections / 181 examples / 630 questions** (530 choice + 100 match; themes 6 and 9 carry 55 choice + 15 match). Every rule section (heading, body ru/en, examples, `exampleTranslations`) and every match question (100 questions, 400 pairs) was read; all choice questions were spot-checked against the unchanged baseline; the question inventory was compared with git HEAD (3.1.0); validator was run read-only. No content or code was modified; only this report was written.

## What passes

- **Question inventory unchanged vs 3.1.0**: all nine files keep 70 questions each (630 total = 530 choice + 100 match; themes 6 and 9 keep their 55 choice + 15 match); ids are identical to the git HEAD baseline, in the same order, and no choice question changed — the pool/UI behaviour is untouched (verified against `git show HEAD:…` for all nine files).
- **No IELTS/TOEFL/exam framing in the app-visible content**: no such strings in titles, summaries, bodies, examples, exampleTranslations, prompts or explanations of the article files; only the internal `art-academic` id/file name and the stale catalog row remain (finding 8).
- **ExampleTranslations** added everywhere and aligned (3.2 feature works; see finding 15).
- **No body/example duplication**: validator-clean; no example string appears in its own body; no example is repeated within a theme.
- **Match format**: every match has 4 pairs; lefts are semantic Russian cues; no cue contains the target article or answer (Latin characters occur only as phonetic hints: “немая h”, [w], [i:], [b], [d]); cues are not trivially word-comparable with the English rights. The specific cue defects are findings 1–3 and 14.
- **Rules restructured sensibly**: the 9 themes are coherently consolidated (system, a/an, the-known, a/an special, zero, names/geography, the-adjective/institutions, contrasts, connected text); each rule has 4–5 bilingual sections, bodies 142–319 characters, no example duplication; the whole 2020-question set validates (`OK: content is valid`); single-file warnings about other sections are mode artefacts.
- **Validator**: all nine article files pass; the only issues above are semantic (validator checks structure, not example-coverage or cue/right sense).

## Recommendation

Fix finding 1 (critical) and findings 2–8 (major) before release; findings 9–14 can go in the same pass (examples/cues are localized). After the example and cue edits, re-run `python3 scripts/validate_content.py app/src/main/assets/data/content` (expect `OK: content is valid`) and re-check the match pairs' semantic mapping (left ↔ right by meaning). The question pools should stay untouched and the `exampleTranslations` must stay aligned 1:1 with `examples`.
