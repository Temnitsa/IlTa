# Design review — IlTa 3.2

**Score: 8/10** — the 3.2 visual pass is a strong, coherent flat design (neutral canvas, white hairline cards, one blue accent, compact type, no decorative noise), and every requested removal/addition is visible and mostly well executed. It does not reach 9/10 because four visible defects break the otherwise clean system: the long-press translation popup (off-palette lavender + elevation + it covers the example being translated), an inconsistent rule-page composition (a long summary inside the progress card for articles/prepositions only), app-bar “short titles” that still ellipsize on four tense rules while being too terse/duplicated on three article rules, and a wrong practice instruction (“Выберите правильный предлог”) on tense questions. All four are localized fixes; with them the same build would read 9–9.5.

Inspected read-only: `art/screenshots/200_home_final.png`, `201_match_final.png`, `203_choice_feedback.png`, `206_settings_about_final.png`, `207_rule_title_short.png`, `208_translation_compact.png`, `195_translation_final.png`; plus code (`Theme.kt`, `Common.kt`, `TopicsScreen.kt`, `SectionScreen.kt`, `RuleDetailScreen.kt`, `PracticeScreen.kt`, `SettingsScreen.kt`) and content titles for the app-bar check. No files except this report were written; no gradle.

## Blockers to reach 9/10

1. **Long-press translation popup is off-system and covers content** (`RuleDetailScreen.kt` — `DropdownMenu(offset = DpOffset(0.dp, -8.dp))`; visible in 208 and 195). It renders with the Material default menu container (pale lavender `#F3EDF7`, not the app palette), with OS-default menu elevation — the only floating widget in a normal reading flow (everything else is flat: cards/bars have no shadow, nav bar elevation is 0; the quick-practice sheet is modal), and anchored at the row top with a negative offset, so it covers the example being translated and overlaps the next row (in 195 «chairs» is hidden behind it; in 208 `ere.` shows at its edge). This breaks DSH flat consistency. **Fix:** replace the menu with an in-place reveal: when the example is long-pressed, expand the translation as a second row inside the same 8dp-radius block (`surfaceVariant` at 38% like the example row, or flat white with a 1dp `outlineVariant` border), full card width, 8dp padding, no elevation; anchor it *below* the tapped example and dismiss on tap-elsewhere. If a floating tooltip is preferred: custom `Popup`/`TooltipBox`, container `MaterialTheme.colorScheme.surface`, 1dp border, 10dp radius, no shadow, caret pointing at the row, positioned so it never overlays the example text.
2. **Rule-page composition is inconsistent between sections** (`RuleDetailScreen.kt` — the progress `AppCard` renders `rule.summary` when `rule.sectionId != "tenses"`). Articles/prepositions rule pages (195) begin with a «Прогресс темы» card that contains a 4–5-line grey descriptive paragraph between the label row and the bar; tense rule pages (207) have a clean two-line progress card. The card mixes two jobs (description vs progress) and the first card changes height/hierarchy from section to section. **Fix:** render the summary as its own block under the app bar (plain paragraph card with no label, 14sp `onSurfaceVariant`), and keep the progress card identical everywhere: level chip + «Прогресс темы» + % + bar. That makes 195 match 207 and removes the paragraph from the progress card.
3. **App-bar “short titles” are not robust** (`RuleDetailScreen.kt`: `title = rule.title.localized().substringBefore(":").trim()…`). Splitting only on “:” gives two failure modes: (a) four tense rules have no colon, so the app bar gets the full 42–64-char title and will ellipsize again (the 3.1 truncation returns): `tense-present-perfect-continuous` “Present Perfect Continuous (настоящее совершённое длительное)” (61 chars), `tense-future-continuous` “Future Continuous — будущее длительное время” (44), `tense-future-perfect` “Future Perfect — будущее совершённое время” (42), `tense-future-perfect-continuous` “Future Perfect Continuous — будущее совершённое длительное время” (64); (b) three article rules collapse to fragments/duplicates — `art-a-an` → “a/an”, `art-a-an-special` → “a/an” (same app-bar title for two different rules), `art-the-known` → “The”. **Fix:** derive the short title from “:”, “ — ” and “ (” in that order (e.g. `substringBefore(":").substringBefore(" — ").substringBefore(" (")`, trim, require length ≥ 3), or better add an explicit `shortTitle`/`shortTitle.en` to the rule JSON for the ~7 affected rules (the English part is already the natural short name: “Present Perfect Continuous”, “Future Continuous”, “Future Perfect”, “Future Perfect Continuous”, “a/an: базовые случаи”, “a/an: особые случаи”, “The: известное”). Verify at 360dp width.
4. **Wrong practice instruction on tense questions** (`PracticeScreen.kt` prompt `when`: the `question.isChoice` branch falls back to «Выберите правильный предлог» for every non-articles section). In 203 a future-simple question (“I promise I will not be late.”) is labelled «Выберите правильный предлог», while the options are verb forms — visible copy inconsistency. **Fix:** make the branch section-aware: `articles` → «Выберите правильный артикль», `prepositions` → «Выберите правильный предлог», otherwise → «Выберите правильный вариант» (for tenses; build/match prompts already read correctly).

## Remaining minor notes (after the four blockers)

1. **Feedback ✓/✕ use text glyphs** while the rest of the app uses line icons (`Icons.Filled.Close` in the practice bar). Use `Icons.Filled.Check`/`Icons.Filled.Close` at 18–20dp inside the verdict row for optical consistency; or keep glyphs but align their size/weight to icons.
2. **About logo reads small:** the 36dp `Image` uses `ic_launcher_foreground`, whose elephant occupies only ~58% of the canvas (adaptive-icon padding), so the visible mark is ~21dp next to a 16sp «IlTa». Use a cropped logo mark (or scale the painter / use the round launcher plate at 40–44dp) so the mark optically matches the title row.
3. **Match grid is slightly ragged:** the two columns are independent `Column`s and each card uses only `heightIn(min = 52.dp)`, so rows do not align when texts have 2 vs 3–4 lines (201). Give all match cards the same fixed height (e.g. 72dp / 3 lines with ellipsis) so the two columns form an even grid.
4. **Match screen whitespace:** the quiz block is top-aligned, leaving ~45% blank at the bottom of 201 on tall screens. Consider centering the two-column block vertically (or moving the tap hint above the columns) so the composition feels deliberate rather than unfinished.
5. **Long-press translation is invisible until tried:** no hint that «Примеры» rows are long-pressable. Add a tiny caption to the «Примеры» label row («долгое нажатие — перевод», 11sp `onSurfaceVariant`) or a one-time hint; otherwise the feature is undiscoverable and its popup issues will likely go unnoticed by users too.
6. **Dark theme not captured:** the screenshot set is light-only; new components (menu/popup, feedback containers, formula tint) rely on theme roles, and the default M3 menu container is exactly the off-palette case — capture one dark-theme set (home, practice feedback, rule page with translation popup) after blocker 1 to confirm.
7. **195 is a stale capture:** it still shows the ellipsized full app-bar title, while the current build shortens colon titles (207). Re-capture 195 for the final gallery after blocker 3 so the deliverable screenshots match the shipped build.
8. **Counters:** home section cards still show «9 тем · 630 вопросов» while rule/theme rows dropped counters — fine if section totals are intentional; otherwise align (not a defect).

**Bottom line:** 8/10. The system itself (palette, cards, radii, type scale, spacing, icon set, hierarchy of primary/secondary actions) is already DSH-grade; the four blockers are local (one popup widget, one card composition, one title-derivation rule, one `when` branch). Fix them, re-capture 195, and add the optional hints — the visual set should score 9–9.5.
